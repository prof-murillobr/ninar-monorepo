Kubernetes na EC2, mensageria na AWS e IA privada.

Uma única EC2 executa k3s com frontend, API, worker e classificador. S3 e SQS cuidam de arquivos e tarefas assíncronas sem exigir um cluster EKS.

Fluxo de uma análise

A API cria a análise e envia uma mensagem leve à SQS. O worker privado consome a tarefa, baixa o áudio do S3, chama o classificador e grava o resultado. O frontend consulta a API para saber quando o status passou a concluído.

  • O worker pode iniciar com concorrência 1 e escalar por réplicas quando a EC2 permitir.
  • A mensagem só é removida da SQS após o resultado ser persistido.
  • O classificador fica acessível somente na rede interna do k3s.

Limite do produto

O resultado é uma hipótese baseada em áudio, não diagnóstico. A interface deve apresentar confiança, permitir “incerto” e nunca prometer uma causa clínica.
